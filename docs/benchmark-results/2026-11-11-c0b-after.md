# C0b 第一步验收：抽出 `v2node-proto` crate

> 日期：2026-11-11 ｜ 依据：`docs/benchmark-spec.md` §5（重构后必须重跑基准判定回退）
> 范围：**仅结构性搬运，不改协议逻辑**。`encryption.rs` 是唯一零 `crate::` 耦合的模块；`vless.rs` / `tls.rs` 仍持有节点状态，角色解耦留到 C0b 第二步。

## 1. 变更内容

| 项 | 变更 |
|---|---|
| workspace | 根 `Cargo.toml` 新增 `[workspace] members = [".", "crates/v2node-proto"]` |
| 新 crate | `crates/v2node-proto`（`v0.1.0`），`pub mod encryption`，1200 行双向 VLESS Encryption 实现从 `src/encryption.rs` 移入 |
| 依赖 | 子 crate 声明 10 个运行时依赖 + `blake3` dev 依赖（单测用它做 derive-key 交叉校验）；主包加 `v2node-proto = { path = ... }` |
| 引用改造 | `src/main.rs` 用 `pub use v2node_proto::encryption;` 保留 `crate::encryption::*` 路径；`vless_probe`、3 个 examples、1 个 bench 全部由 `#[path]` 改为 crate 引用，**`#[path]` hack 清零** |
| lints | `[lints.rust]` / `[lints.clippy]` → `[workspace.lints.*]`，两个 package 各加 `[lints] workspace = true` |
| 门禁范围 | `Makefile` 与 CI `rust.yml` 全部命令加 `--workspace` / `--all`，新 crate 纳入硬门禁 |

## 2. 门禁结果（本机实测）

| 命令 | 结果 |
|---|---|
| `cargo fmt --all -- --check` | 通过 |
| `cargo clippy --workspace --all-targets -- -D warnings` | 通过，0 warning（两个 crate 均检查） |
| `cargo test --workspace` | **64 passed / 0 failed** |
| `cargo check --workspace --all-targets --all-features` | 通过 |
| `cargo bench --bench proto_bench --no-run` | 通过 |
| `git diff --check` | 通过 |

**测试分布变化说明（不是覆盖减少）**：此前 `cargo test` 显示 64 + 9 = 73，其中 9 个 encryption 单测因 `#[path]` 在主 bin 与 probe bin **各编译运行一次**。抽出 crate 后为 `v2node-proto` 9 + 主 bin 55 = **64 个唯一测试**，重复副本被消除，唯一测试集合不变。

## 3. 基准 before/after（同一台机器、同一命令 `cargo bench --bench proto_bench`）

| Workload | 重构前（基线） | 重构后 | 变化 |
|---|---:|---:|---:|
| W1 `derive_key_raw` | 165.63 ns | 183.00 ns | **+10.5%** |
| W2 `ClientEncryptionConfig::parse` | 165.69 ns | 166.69 ns | +0.6% |
| W3 `EncryptionServer::from_decryption` | 13.128 µs | 12.985 µs | -1.1% |
| W4 AES-256-GCM seal 8192B | 2.1862 µs | 2.1553 µs | -1.4% |
| W5 AES-256-GCM open 8192B | 2.2060 µs | 2.1952 µs | -0.5% |
| W6 pump 式分配+拷贝 8192B | 193.19 ns | 201.97 ns | +4.5% |

**W1 复测与排查**：
- 单独复测 W1 = 179.92 ns（与 183.00 差 1.7%），两轮区间不重叠于基线，确认是**稳定的可观测变化**，非噪声。
- 试加 `#[inline]` 后复测 = 179.93 ns（change +0.56%，p = 0.33），**无效，已撤销该改动**，不保留无依据修改。
- 推测与跨 crate 编译单元布局 / bench profile 未启用 LTO 有关，尚未定位。

## 4. 回归判定（按 `benchmark-spec.md` §5）

**判定：不宣称「零回退」，标记 1 项待复核。**

- W1 按百分比超过 5% 阈值；W6 接近阈值。但绝对值差约 15 ns / 9 ns，占 L2 完整握手 484 µs 的比例不足 0.01%，**工程影响可忽略**。
- P99 逐次探针受 Windows `Instant` 约 100 ns 粒度限制，不足以据其判定；正式判定以 criterion 区间估计为准。
- 结论：结构性重构本身可验收（协议逻辑未改、单测与门禁全绿），但「性能无回退」需评审确认上述偏差为**已记录的可接受偏差**，或在 `<BUILD_HOST_IP>` Linux 构建机复测排除 toolchain 差异后再下结论。

## 5. 遗留项（C0b 完成验收的硬前置）

1. **Linux 全量回归**：8 套 E2E + `interop_xray.sh`（Xray v26.11.9 双向）必须在构建机跑通，本机不可执行。
2. **W1 偏差复核**：如上，需评审豁免或 Linux 复测。
3. **C0b 第二步角色解耦**：把 VLESS 帧 / 地址编解码从 `VlessContext`（持有 `NodeState` / `RuntimeConfig` / `NodeInfo`）中剥离；`tls.rs` 客户端/服务端角色分离。见 `docs/client-design-plan.md` §4。
4. 移除 `src/main.rs` 的兼容 `pub use`，改为直接 `use v2node_proto::...`。
