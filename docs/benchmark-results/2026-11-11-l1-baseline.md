## 3. 解读

1. **加密算术不是瓶颈**：W4/W5 约 2.23–2.29 µs/记录、3.4–3.5 GiB/s，硬件加速路径已生效。这印证 `client-design-plan.md` 附录 C.3 的判断——手写加密汇编不应作为优化方向。
2. **W3 单次数值最大但优化价值有限**：14.52 µs 主要来自 X25519 公钥计算，且它是**配置构造**（每次配置加载调用一次），不是每连接热路径。单次数值大 ≠ 优先级高，必须结合调用频次判断。
3. **对上一版判断的下修**：W6（分段分配 + 拷贝）205.2 ns，约为 W4 的 9%。上一版把「分配与拷贝」列为主要热路径，首批数据提示其在单条记录上的收益上限约 10% 量级，而非主导项。W6 是模拟实现、W4 已含输出分配，两者不可直接相减；**优先级须在 L2 组件层测完整 pump 后再定**，不据此前判断启动零拷贝改造。
   > **本条已被 L2 结果修正（结论反转）**：完整 pump 单会话仅 1,115 MiB/s，约为裸 AEAD 的 1/3，差额来自分片、输出 `Vec`、双层 `DuplexStream` 拷贝与调度，而非单次分配。详见 `docs/benchmark-results/2026-11-11-l2-baseline.md` §3.2。L1 微基准不足以判断管线级优化优先级。
4. **W1/W2 均低于 200 ns**，属亚微秒级，不是优化重点。手写标量 BLAKE3 虽比 SIMD 慢，但只在握手路径调用，总量可忽略。
