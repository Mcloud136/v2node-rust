## 3. 解读

1. **量化了系统调用边界的成本**：与 L2（`DuplexStream` 内存流，0.90 ms / 1,115 MiB/s）相比，真实 TCP 回环使 1 MiB 单会话变为 1.76 ms / 568.5 MiB/s，**吞吐约减半、耗时约翻倍**；握手由 484.1 µs 增至 607.8 µs（+25.6%）。这印证「用户态语言改不了系统边界」——Rust 重构的收益上限在用户态处理，不在这部分。
2. **4 worker 下 32 连接已饱和**：8 并发聚合 955 MiB/s，32 并发 901 MiB/s，略降。结合 L2 的 worker 扩展曲线（4 worker 后收益递减），桌面端 4 worker + 中小并发是经济区间。
3. **W13 的 1 会话值（3.01 ms）与 W12（1.76 ms）不可直接比较**：W13 每次新建 runtime、经 `tokio::spawn` 且计时范围覆盖任务调度，属「阶梯测量」口径；W12 是单会话直测。两者只用于各自组内趋势比较。
4. **口径限制**：数字含 harness 的 socket 与任务调度开销；未接 mock 面板 / 订阅，未采 RSS 与每连接增量内存；32 连接阶梯不等同于规范 W10 的 1/40/200/1000 生产阶梯。
