# L2 组件层首批基线（2026-11-11）

> 规范依据：`docs/benchmark-spec.md` v1.0（L2 组件基准 / W7、W9、W10）
> 状态：**baseline 种子**。覆盖吞吐与多线程两维；**不得用于跨语言结论**。

## 1. 元数据与复现

| 项 | 值 |
|---|---|
| 归档字段 | `2026-11-11, 0d5a063, Rust, rustc 1.99.1, W7/W9/W10, L2, us|ms|MiB/s, median-of-5, working-tree-local` |
| 提交 | `0d5a063`（含本轮未提交改动，结果对应 working tree） |
| 编译器 / 架构 | rustc 1.99.1 / x86_64 / Windows 本地开发机 |
| profile | `--release`；`lto=thin`、`codegen-units=1`、`strip=true` |
| workload | 1 MiB payload、`duplex` 容量 65,536 B、5 轮中位数、并发 8 |
| harness | `examples/bench_l2_pump.rs`，零外部依赖，`#[path]` 复用 `src/encryption.rs` |
| 复现命令 | `cargo run --release --example bench_l2_pump` |
| 网络 IO | **无**（`DuplexStream` 内存流，走完整握手 + 加密泵） |

**口径提醒**：数字**包含 harness 的 `DuplexStream` 读写与调度开销**，是组件层上限，不等于纯产品代码开销；不可直接与 L1 裸 AEAD 数字相减归因。

## 2. 结果

| Workload | 结果 |
|---|---|
| W7 完整握手（median of 5） | **484.1 µs** |
| W9 单会话 1 MiB（median of 5） | **0.90 ms / 1,115.0 MiB/s** |

W10 worker 扩展性（8 并发 × 1 MiB，5 轮中位数）：

| worker 数 | 总耗时 | 聚合吞吐 | 加速比 |
|---:|---:|---:|---:|
| 1 | 13.91 ms | 575.2 MiB/s | 1.00x |
| 2 | 6.96 ms | 1,148.9 MiB/s | **2.00x** |
| 4 | 4.12 ms | 1,940.1 MiB/s | 3.37x |
| 8 | 3.39 ms | 2,359.3 MiB/s | 4.10x |

## 3. 解读

1. **多线程能力（D 维首个实测）**：1→2 worker 近线性（2.00x），1→4 为 3.37x，1→8 为 4.10x，**4 worker 之后明显收益递减**。桌面端默认 4 worker 比 8 更经济；8 worker 的额外收益约 22%。
2. **对 L1 解读第 3 条的修正（结论反转）**：L1 依据 W6（205 ns 分配+拷贝）曾判断「零拷贝收益上限约 10%」。L2 显示完整 pump 单会话仅 1,115 MiB/s，约为裸 AEAD（3,505 MiB/s）的 1/3；折算每 8192 B 记录约 7 µs，而裸 AEAD 约 2.23 µs。差额来自 8192 分片、AEAD 输出 `Vec`、两层 `DuplexStream` 拷贝与任务调度，**不是单次 `Vec` 分配**。因此 L1 的 W6 低估了管线开销：**零拷贝 / 缓冲池值得在 L2 逐段打点后重新评估**，但须先剥离 harness 开销，不能把全部差额归因于产品代码。
3. **握手是短连接主要成本**：484 µs 约为单会话 1 MiB 传输（0.90 ms）的 54%。M1 不支持 0-RTT 会话恢复（`docs/vless-encryption-prod.md` §7.1），这是协议层真实且可量化的优化空间，但需要两端配合，属 N2 之后。
4. **与节点侧数据不可直接比较**：节点侧「16 并发 × 1 MiB 服务端 CPU 0.11–0.14s」是 CPU 时间口径；此处是 wall-clock 聚合吞吐，且为客户端出站方向。两者只沿用趋势，不比绝对值。

## 4. 覆盖与符合性缺口

| 维度 | 状态 |
|---|---|
| 延迟 | 握手已测中位数；**P50/P99 逐次分布未采集** |
| 吞吐 | 已测（单会话与聚合） |
| 内存 | **未测**（RSS / 每 MiB 分配计数待接入） |
| 多线程 | **已测** 1/2/4/8 worker 扩展曲线 |
| Go 对照组 | **阻塞**：本机 `go: command not found`，需在 `<BUILD_HOST_IP>` 构建机或安装 Go 后执行 |
| 轮次 | 5 轮中位数，符合 `benchmark-spec.md` §4 |

**声明**：本批满足「≥5 轮中位数」，但仍缺 P50/P99 逐次分布、内存维度与 Go 对照组，且含 harness 开销，因此**不得用于「Rust 比 Go 快」一类跨语言结论**。
