# C0b Linux E2E 与 Xray 互通验证（构建机权威环境）

> 日期：2026-11-11 21:10
> 用途：C0b 重构（抽取 `v2node-proto` crate）在权威 Linux 构建机的全量回归，作为 G1 门控输入
> 结论：**C0b 重构在权威 Linux 环境零回归，且与 Xray v26.11.9 互通完整**

---

## 环境

| 项 | 值 |
|---|---|
| 构建机 | `<BUILD_HOST_IP>`（hostname `ops`），Linux 7.0.0-38-generic x86_64 |
| 工具链 | cargo 1.99.1 / rustc 1.99.1（`/root/.cargo/bin`），Python 3.14.4 |
| Xray | `/opt/xray-test/xray` —— **Xray 26.11.9**（go1.27.3 linux/amd64），满足互通最低版本要求 |
| 源码 | 重新克隆 `main` 至 `9adff42`（`/opt/v2node-rust`，depth 1，含 C0b 的 `crates/ benches/ examples/`） |
| 构建目录 | `CARGO_TARGET_DIR=/opt/v2node-rust-target`（复用既有 9.4G 缓存） |

> 注：构建机原 `/opt/v2node-rust` 为非 git 源码副本且停留在 C0b 之前，已改名备份后重新克隆到 `9adff42`，恢复为标准 git 形态。

## E2E 三连（`BIN=/opt/v2node-rust-target/debug`，默认端口，互不冲突）

| 脚本 | 结果 | 覆盖 |
|---|---|---|
| `tests/e2e.sh` | `E2E_PASS` | TCP/UDP/early-data 转发、用户热更新（旧 UUID 拒绝）、节点配置热更新（旧路径拒绝）、进程 PID 不变 |
| `tests/e2e_encryption.sh` | `ENC_E2E_PASS` | `mlkem768x25519plus` native/xorpub/random 三模式握手；配置热切换；关加密后旧加密客户端被拒 |
| `tests/interop_xray.sh` | `INTEROP_ALL_PASS` | Rust 服务端↔Xray 客户端、Xray 服务端↔Rust 客户端，native/xorpub/random 三模式 GET 200003B / POST 100000B 一致；Xray 版本确认为 26.11.9 |

## 结论

- C0b「抽取 `v2node-proto` workspace crate + `#[path]` 清零 + `[workspace.lints]`」在权威 Linux 环境全量门禁与 E2E 零回归。
- 加密节点与 Xray v26.11.9 双向互通完整，C0c 灰度与 C0d PoC 的加密链路基础已验证。
- **C0b 第二步（角色解耦：从 `vless.rs` 抽纯帧编解码 / 计量分离）仍待做**，最终回归同样以本环境为准。

## 复现命令

```bash
cd /opt/v2node-rust
export CARGO_TARGET_DIR=/opt/v2node-rust-target
export PATH=$HOME/.cargo/bin:$PATH
make quality && cargo build --bins
export BIN=/opt/v2node-rust-target/debug
bash tests/e2e.sh && bash tests/e2e_encryption.sh && bash tests/interop_xray.sh
```
